RL Feedback Loops

Mid-session reordering: Stage 7 (SceneExecutor) detects scene completion → RLService.recordReward(engagementSignals) → Thompson Sampling updates → ScenePipelineOrchestrator.reorderPendingScenes(updatedPolicy) → back to Stage 5.

Cross-session learning: Session ends → LearnerProfileService.save(updatedProfile) → Next session: LearnerProfileService.load(userId) → Stage 4: StoryboardEngine.plan(graph, updatedProfile) → Anchors explanation to masteredConcepts/struggledConcepts.

Stage 1

User Prompt

INPUT

Raw user input: a topic string or question.

Stage 4

Storyboard — Mission-Driven Plan

OUTPUT OF StoryboardEngine.plan(graph, learnerProfile)
StoryboardEngine — Claude PLANNER_SYSTEM_PROMPT, validated by StoryboardValidator

Pedagogically ordered scenes with narration manifests. agentCommands and syncMarkers are empty — the compiler fills them during scene preparation.

Data Structure

interface Storyboard { id, title, topic: string; generatedAt?: number; targetUser?: { expertise, goal, userId, roadmapPosition, presentationPreferences }; scenes: StoryboardScene[]; parameters: ParameterDefinition[]; voiceScript?, narrationManifest?: NarrationManifest; interactionPoints: InteractionPoint[]; metadata?: StoryboardMetadata; } interface StoryboardScene { // Planner output — agentCommands filled by compiler id, name, narration: string; nodeIds?: string[]; checkpointName: string; // Required — assigned by planner or fallback (scene-{nodeId}) focusNodeId?: string; durationEstimate?, estimatedDurationSeconds: number; agentCommands: AgentCommand[]; // Empty from planner syncMarkers?: SyncMarker[]; viewport: ViewportState | PlannerViewport; interactiveParameters: string[]; transitionFrom?, branches?: Branch[]; scaffolding?: ScaffoldingHint; } interface PlannerViewport { zoom: number; center: { x, y }; } interface ScaffoldingHint { emphasizeNodeIds: string[]; analogyContext, difficultyContext, suggestedVisualMetaphor: string | null; }

ParameterDefinition

interface ParameterDefinition { name, label: string; type: ParameterType; // integer | float | boolean | string | enum default: unknown; min?, max?, options?, enumValues?; bindings: ParameterBindingSpec[] | ParameterBindingRecord[]; exposedInScenes?, semanticTarget?; }

Stage 5

VisualScript — Frame-Based Visual Narrative

OUTPUT OF AgentOrchestrator.orchestrateScene() → VisualScriptGenerator.generateScript()
ScenePipelineOrchestrator.prepareAllScenesFromStoryboard() — concurrent VisualScript + TTS

For each StoryboardScene: storyboardSceneToPresentationScene → orchestrateScene (with scaffolding) → VisualScript. TTS in parallel. Rescale timings to real audio. compileStoryboardScene produces executable StoryboardScene.

Intermediate: PresentationScene (internal)

interface PresentationScene { id, focusNodeId: string; nodeIds, edgeIds: string[]; narration: string; viewport: { x, y, zoom }; visualCommands: VisualCommand[]; durationEstimate: number; visualScript?: VisualScript; // Populated by pipeline illustrations?, sceneContract?; }

Data Structure: VisualScript

interface VisualScript { sceneId: string; frames: IllustrationFrame[]; totalDuration: number; entities: Record<string, VisualEntity>; } interface IllustrationFrame { id: string; startTime, endTime: number; entities: VisualEntity[]; transitions?: EntityTransition[]; narrationSegment, description: string; } interface VisualEntity { id: string; type: VisualEntityType; // Server, Pod, Arrow, Equation, Graph2D, etc. position: { x, y }; // 0-100% size: { width, height }; label?, color?, highlight?; animation?: { type, duration, delay }; sourceEntityId?, targetEntityId?; // For Arrow/DataFlow parentEntityId?; // Hierarchical nesting textContent?, codeLanguage?; metadata?: Record<string, any>; }

Stage 6

StoryboardScene — Executable Agent Commands

OUTPUT OF compileStoryboardScene() — shared/VisualScriptCompiler
VisualScriptCompiler — VisualScript → AgentCommand[] + SyncMarker[]

Frames become createElement, fadeIn, moveTo, fadeOut. Viewport normalized (PlannerViewport → ViewportState). SyncMarkers bind timed commands to word indices. Parameter bindings inferred from ENTITY_PARAMETER_MAP.

Transformation: VisualScript → AgentCommand[]

Each frame entity: createElement (timing: frame.startTime + delay) → fadeIn (await-previous). Position changes → moveTo. Removed entities → fadeOut. Commands with timing > 0 and wordTimestamps → SyncMarker.

Data Structure

interface StoryboardScene { id, name, narration: string; nodeIds?, focusNodeId?: string; checkpointName: string; // Required — every scene navigable agentCommands: AgentCommand[]; syncMarkers?: SyncMarker[]; viewport: ViewportState; interactiveParameters: string[]; estimatedDurationSeconds: number; } interface AgentCommand { method: string; // createElement, fadeIn, moveTo, zoomTo, panTo, setParameter, etc. args: Record<string, unknown>; timing: 'immediate' | 'await-previous' | number; } interface SyncMarker { wordIndex: number; command: AgentCommand; } interface ViewportState { x, y, zoom: number; rotation?, focusElementId?, bounds?; }

WebSocket Delivery

Gateway sends scene_change with StoryboardScene (agentCommands + syncMarkers), then narration_text, then agent_audio_meta (durationMs, wordTimestamps only — no visualScript), then binary audio. Frontend uses agentCommands from scene_change as the single source of visual truth.

↓
Stage 7

Frontend — Rendered Illustrations

sessionStore.currentScene → SceneGraphPresenter → useSceneEngine → SceneExecutor → FrameRenderer
SceneExecutor.execute(scene) runs AgentCommand[] against EnvironmentAPI

Each createElement adds SceneElement to SceneGraph. fadeIn/moveTo update element state. Dirty render cycle updates only changed elements (Law 3).

Data Structure: SceneElement (Engine State)

interface SceneElement { id: string; // "sceneId:entityId" type: StageElementType; // box | circle | arrow | text | code | diagram | label | connection | group position: Vector2; visible, opacity, zIndex; properties: { visualEntityType, label, color, width, height, ... }; boundParameters?: string[]; }

Transformation: elementToVisualEntity

SceneElement → VisualEntity: pixel position → percentage, extract visualEntityType, label, color, size from properties. Strip sceneId: prefix from id.

ExecutionResult

interface ExecutionResult { status: 'complete' | 'aborted'; completedCommands: CommandResult[]; failedCommand?, error?; }

Final: FrameRenderer → SVGLibrary

VisualEntity[] dispatched by type to 40+ SVG components (Server, Pod, Arrow, Equation, Graph2D, etc.). Canvas 1600×900 (CANVAS_WIDTH × CANVAS_HEIGHT).

Stage 7b

Interaction Paths

Two critical user interactions are handled outside the main pipeline. Documenting them explicitly prevents future implementers from assuming server round-trips where none exist.

Checkpoint Restore

User clicks checkpoint in timeline
  1. Client sends: { type: 'restore_checkpoint', name: 'Service Introduction' }
  2. Gateway: CheckpointManager.restoreCheckpoint(session, name)
  3. SceneGraph state replaced from SceneSnapshot (<100ms)
  4. All elements marked dirty
  5. Gateway sends: { type: 'checkpoint_restored', checkpointName, sceneId }
  6. Frontend: SceneGraph re-renders dirty elements
  7. AudioPlaybackManager.seekTo(snapshot.narrationOffset)

Parameter Change (Frontend-Only)

User changes parameter slider — no server round-trip
  1. Client sends: { type: 'set_parameter', name: 'pod_count', value: 3 } (for sync to other clients)
  2. Frontend: EnvironmentAPI.setParameter('pod_count', 3)
  3. SceneGraph: bindings propagate via MapperRegistry, elements marked dirty
  4. Next render frame picks up dirty elements (<16ms)
  5. No server call required — Law 2 (Parameters Over Regeneration)
