Section 01

The Paradigm Shift: From Text Dumps to Active Teaching

Current AI assistants — Perplexity, ChatGPT, Claude — receive a question, generate a monolithic text response, and relinquish control. The user is left to parse, comprehend, and synthesize unaided. Version 2 inverts this entirely.

Generates monolithic text. User must self-navigate. No adaptation. No visual aids. No interruptibility. Knowledge vanishes after scrolling.

🎬

V2: Active Presenter

Constructs a knowledge graph, presents visually with voice narration, handles interruptions, adapts to how the user learns, and resumes seamlessly.

CORE PRINCIPLE

The Agent is not answering a question — it is teaching a concept. Every response is a structured lesson derived from a live knowledge graph, delivered through voice and visuals, adapted in real-time to the learner's comprehension patterns.

CURRENT VISUAL SCOPE

The system currently has 30+ SVG entity types optimized for IT/CS infrastructure topics (servers, databases, pods, containers, networks). The visual vocabulary is actively being expanded to support math, physics, and general education — see the Ship Roadmap for planned entity types including equations, coordinate systems, and physics diagrams.

Phase 1 — Reasoning + Classification (Combined)

The Agent uses Claude Sonnet 4.5 (claude-sonnet-4-5-20250929) to perform conceptual decomposition and classification in a single reasoning call. Rather than separate Reasoner and Classifier services, the system prompt instructs Claude to output a structured JSON artifact containing: conceptual primitives with their DataType, relationships with their EdgeType, prerequisite dependencies, complexity gradient, and visual hints for each node.

Phase 2 — Knowledge Graph Construction

The KnowledgeGraphService builds the graph in concentric depth layers using in-memory JavaScript objects (Record<string, KGNode>). Depth 0 (root topic) and Depth 1 (immediate sub-concepts) are built synchronously before the presentation begins. Deeper layers (depth 2+) are expanded asynchronously in the background with RL-prioritized node selection.

Phase 3 — Presentation Planning

The PresentationPlanner receives the knowledge graph and the RL agent's recommended traversal policy, then generates a scene sequence — an ordered list of scenes, each focusing on 1 node with its connecting edges. The planner enforces single-node-per-scene granularity for fluid presentation pacing.

Phase 4 — Concurrent Scene Preparation

The ScenePipelineOrchestrator prepares scenes concurrently via a ConcurrencyPool. For each scene, two tasks run in parallel: the VisualScriptGenerator asks Claude to produce a frame-based visual script (entity types, positions, animations), and the VoiceService generates TTS audio with word-level timestamps from ElevenLabs. Once both complete, the visual script's timing is rescaled to match the actual audio duration. Scenes stream to the frontend as they become ready — no blocking on full preparation.

WHY BOUNDED EXPANSION MATTERS

Without bounds, "Kubernetes Networking" could expand into hundreds of nested scenarios. The RL agent predicts which 2-3 branches the specific user is most likely to explore, and only pre-expands those. If the user asks an unexpected question, the graph mutates on-demand via the interrupt protocol.

PLANNED — PERSISTENT GRAPH STORE

Currently graphs are stored in-memory and lost when the session ends. A future Neo4j integration will enable persistent graph storage, cross-session graph reuse, and Cypher-based traversal queries.

Input — MediaRecorder to Deepgram

The client uses the MediaRecorder API (not WebRTC streaming) to capture audio. The user clicks a microphone button to start recording and clicks again to stop. On stop, the recorded audio is combined into a single audio/webm blob and sent as a binary WebSocket message to the backend. The backend forwards this to Deepgram (nova-2 model) for transcription with word-level timestamps and smart formatting.

PLANNED — STREAMING VAD

A future version will implement Silero VAD on the client for real-time voice activity detection, enabling continuous listening and streaming audio chunks instead of manual mic toggle. This will reduce latency and enable true conversational interaction.

Output — ElevenLabs + AudioPlaybackManager

Narration text is sent to ElevenLabs (eleven_turbo_v2_5 model, voice "George" JBFqnCBsd6RMkjVDRZzb) using the /with-timestamps endpoint, which returns both audio and character-level alignment. The backend converts character alignments to word-level timestamps. Audio is sent as binary over WebSocket; timestamps and visual scripts are sent as JSON via agent_audio_meta.

On the client, the AudioPlaybackManager (singleton) manages playback via the Web Audio API. It maintains a single AudioContext, decodes incoming MP3 buffers, and uses latest-wins semantics (new audio cancels any current playback). A requestAnimationFrame loop tracks playback time and drives visual synchronization via a callback into the Zustand store.

Sound Effects — SoundEffectEngine

The SoundEffectEngine (singleton) generates procedural audio effects using the Web Audio API — no external sound files. It provides four effects: a reveal pop (sine 800→400 Hz, 50ms), a connect ping (sine 1200→800 Hz with echo), a transition whoosh (bandpass-filtered white noise sweep), and a chime (C5+E5 two-tone sequence). All effects are routed through a master gain node at 15% volume to remain subtle.

Intent Classification — Pattern-Based

While the agent is presenting, incoming user speech is classified into one of four intents using regex-based pattern matching (not ML). This provides fast, deterministic classification without additional API calls:

CONFUSION "don't understand", "what?", "confused", "repeat" Rephrase current node with alternate analogy/example

SEAMLESS RESUMPTION

When resuming, the agent uses a bridging phrase ("So, as we were saying..." / "Coming back to..." / "Now, where were we...") and resumes narration from the exact word offset. The newly added graph nodes from the interrupt remain visible but dimmed, maintaining spatial context of what was just explored.

Section 07

Reinforcement Learning for Personalized Cognitive Scaffolding

The RL subsystem continuously learns how the specific user best absorbs new concepts and adapts the presentation strategy in real-time. It uses a Contextual Bandit with Thompson Sampling — lightweight enough to update in under 50ms per reward signal.

Thompson Sampling — Implementation Detail

Each strategy/pace/density option is modeled as a Beta-distributed arm with initial priors alpha=2, beta=2. On a positive reward, alpha += reward.value. On a negative reward, beta += |reward.value|. The policy is resampled after each reward signal: for each arm, a random value is drawn from Beta(alpha, beta), and the arm with the highest sampled value is selected.

ScenePresenter Layout

The ScenePresenter provides a card-based layout focused on one knowledge graph node per scene. The main area contains the IllustrationCanvas (1600×900 SVG viewBox) rendering the current visual script. Below the canvas, a SubtitleDisplay shows word-level synchronized captions. A sidebar provides three tabs: Info (session state + node list), Graph (knowledge graph node list), and Chat (text interaction).

Frame-Based Visual Scripts

Each VisualScript contains an array of frames, where each frame has a startTime, endTime, and a list of VisualEntity objects. The IllustrationCanvas selects the active frame based on the current audio playback time, then passes its entities to the FrameRenderer.

To ensure smooth transitions, the canvas uses a sliding window: entities from the previous frame bucket are merged with the current frame's entities. Previous-frame entities are deep-copied to prevent cross-frame mutation, a fix that resolved a position drift bug where layout processing in one frame could corrupt shared entity references.

Double-<g> Pattern

Every SVG component uses a double <g> structure to separate positioning from animation. The outer <g> applies transform="translate(x, y)" for static positioning via SVG attributes. The inner <g> receives CSS animation classes (illus-fadeIn, illus-scaleIn, illus-slideIn, illus-pulse, illus-flow, illus-dashFlow) with transform-origin: center and transform-box: fill-box. This prevents CSS transforms from overriding SVG positioning and eliminates the "snap to origin" animation bug.

Currently only Focus Mode (single-scene view) is implemented. Planned additions include: Graph Mode (bird's eye view of the entire knowledge graph), Transition Mode (animated zoom between focus areas), and a minimap overlay showing the current position within the larger graph.

Section 09

Session State Machine

The entire session lifecycle is governed by a finite state machine with seven states. Transitions are deterministic and emitted to the frontend via state_change WebSocket events.

Fig 9.1 — Session State Machine
stateDiagram-v2 [*] --> Idle: Session created Idle --> Listening: User speaks or types Listening --> Reasoning: Transcript complete Reasoning --> BuildingGraph: Classification done BuildingGraph --> Presenting: Core graph ready Presenting --> Interrupted: QUESTION intent detected Interrupted --> Presenting: Answer presented + resume from bookmark Presenting --> Completed: All planned nodes presented Completed --> Listening: User asks new topic Completed --> [*]: Session ends Interrupted --> Presenting: User says "never mind"

The seven states — IDLE, LISTENING, REASONING, BUILDING_GRAPH, PRESENTING, INTERRUPTED, and COMPLETED — are tracked as a top-level enum. Within the PRESENTING state, the presentation loop handles scene transitions, narration pacing, and comprehension checks procedurally rather than as discrete sub-states. The interrupt protocol (§6) transitions to INTERRUPTED and back to PRESENTING using the bookmark mechanism.
