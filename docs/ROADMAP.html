THE CRITICAL GAP

The visual vocabulary is heavily skewed toward IT infrastructure diagrams (Server, Database, Pod, Container). There is zero support for equations, coordinate systems, geometric constructions, function plots, or scientific illustrations. The agent cannot teach calculus if it can only draw servers. Phase 1 is the make-or-break investment.

Phase 0 — 1 Week

Stabilize and Harden

Fix what is broken or fragile so we have a reliable foundation to build on.

  • ✅
    Position drift fix — Double-<g> structure in SVGLibrary separates positioning from CSS animations; deep-copy entities across frames to prevent cross-frame mutation.
  • ⬜

    Error boundaries — Add React error boundaries in App.tsx around ScenePresenter and Sidebar so rendering failures don't crash the app.

  • ⬜
    Backend test gaps — Add integration tests for AgentService.reason() and VoiceService to catch regressions.
Phase 1 — 2-3 Weeks

Universal Visual Vocabulary

The highest-priority phase. The agent cannot teach math or physics if it can only draw servers and databases. We need a visual vocabulary that works for any subject.

WHY THIS IS THE MAKE-OR-BREAK PHASE

The rendering pipeline (VisualScript → IllustrationFrame → FrameRenderer → SVGLibrary) is designed to be extensible. Adding new entity types is mechanical: define the type, add the SVG component, teach the agent about it. The pipeline itself does not need to change. Once the agent can render equations, plot functions, and draw force diagrams, everything else already works.

Add LaTeX-to-SVG rendering so the agent can display equations, expressions, and derivations.

Phase 2 — 2-3 Weeks

Domain Engines

Build specialized capabilities for key domains: code execution, interactive math solving, and physics simulation.

💻

2a. Code Execution Engine

Sandboxed execution (Docker-in-Docker or WebAssembly). Agent generates + runs code snippets during explanations. Output rendered as syntax-highlighted CodeBlock entities. Critical for CS topics.

🧮

2b. Interactive Math Solver

Agent solves equations step-by-step, showing each algebraic transformation. Each step = a visual frame with the equation entity animating the change. Supports algebra, calculus, linear algebra.

🚀

2c. Physics Simulation

Projectile motion, wave propagation, orbital mechanics, spring/pendulum. Animated SVG paths with time-based interpolation. Parameters driven by narration context.

Phase 3 — 2 Weeks

Learning Loop and Interaction

Turn the system from a one-way presenter into an interactive tutor with comprehension checks, persistent learning profiles, and multi-modal input.

🎯

3a. Comprehension Checks

The RL service already has shouldCheckComprehension() but it is never exercised. Implement pause-and-quiz: agent poses a question, evaluates the answer, and adjusts the RL policy. Extend InterruptHandler for agent-initiated pauses.

💾

3b. Learner Model Persistence

Add PostgreSQL/SQLite for session persistence. Store session history, learner profiles, RL parameters, and KG snapshots. Enable "continue where you left off" across sessions.

📷

3c. Multi-Modal Input

Accept image uploads (homework photos, whiteboard, textbook pages). Use Claude's vision to extract the problem. Generate a presentation that solves/explains the captured content.

Phase 4 — 1-2 Weeks

Production Readiness

Ship-quality infrastructure: CI/CD, monitoring, performance, and multi-tenancy.

CI/CD Pipeline

GitHub Actions: lint, type-check, test (backend + frontend), build Docker images, deploy. Automated PR checks with coverage thresholds.

Monitoring & Observability

Structured logging with correlation IDs. Health dashboard: API latency, TTS/STT success rates, WebSocket connections. Error tracking (Sentry).

Performance Optimization

Tune concurrent scene preparation pool sizes. Lazy-load SVG components. CDN for static assets. WebSocket message batching.

Authentication & Multi-Tenancy

User accounts (JWT + OAuth). Session isolation. Rate limiting per user. Usage tracking.

THE BOTTOM LINE

The architecture is strong. The concurrent scene pipeline, the RL scaffolding, the interrupt protocol, the frame-based visual system — these are genuinely sophisticated. The biggest risk is not architecture; it is visual expressiveness. An agentic tutor that can only draw IT diagrams will fail to teach calculus or Newtonian mechanics.

Ship Phase 0+1, and you have a demo that can teach math. Ship through Phase 3, and you have a product.
